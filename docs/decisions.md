# Beslutninger

## 1. Separat projekt

Projektet ligger ved siden af bookingsystemet, saa de to kodebaser ikke blandes
sammen.

## 2. Native app til medlemmer

Appen er til eleverne og skal foles som et rigtigt socialt klassehub.

## 3. Web/admin til opsaetning

Oprettelse af klasse, skole, indstillinger og moderation bor ske paa web, fordi
det er nemmere at arbejde med formularer, tabeller og admin-flows der.

## 4. API som kilde til sandhed

App og web/admin skal tale med samme API, saa data, roller og rettigheder holdes
samlet.

## 5. Multi-class fra start

Datamodellen skal fra starten tage hojde for flere skoler, flere klasser og
flere brugere i samme system.
